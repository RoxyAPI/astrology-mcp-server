# AGENTS.md

Astrology MCP server by RoxyAPI. A stdio MCP server that relays `tools/list` and `tools/call` to the hosted RoxyAPI Remote MCP servers at `https://roxyapi.com/mcp/{domain}`.

## Layout

| Path | Purpose |
|---|---|
| `src/proxy.ts` | Connects one client per domain, merges the tool catalogs, routes each call to the domain that owns the tool |
| `src/index.ts` | Entry: reads `ROXY_API_KEY` and `ROXY_MCP_DOMAINS`, serves over stdio |
| `tests/proxy.test.ts` | Catalog merge and call routing against in-memory upstreams |
| `tests/live.test.ts` | Spawns the built server and lists the hosted tools |
| `scripts/sync-docs.ts` | Regenerates the README domain table and tool count from the live spec and servers |
| `manifest.json` | Desktop extension manifest, packed by `bun run pack:mcpb` |
| `server.json` | MCP Registry entry for the remote and the npm package |
| `Dockerfile` | Container image that serves over stdio |

## Commands

```bash
bun install
bun run check      # biome
bun typecheck
bun run test       # builds dist/index.js, then runs both test files
bun run docs:sync  # rewrites the generated README regions
bun run pack:mcpb  # builds astrology-mcp-server.mcpb
```

## Rules

- Tools come from the hosted servers. Never define, rename or rewrite a tool here.
- Domain slugs come from the hosted servers. Never hardcode a list in code.
- `package.json`, `manifest.json` and `server.json` carry one version; the release workflow bumps all three.
- README regions between `<!-- BEGIN:DOMAINS -->` and `<!-- END:DOMAINS -->`, and between `<!-- BEGIN:TOOLS -->` and `<!-- END:TOOLS -->`, are generated by `bun run docs:sync`. Never edit them by hand. A domain appears when the spec has its tag and `https://roxyapi.com/mcp/{slug}` lists tools.

## Releases

`release.yml` runs daily and on dispatch. It syncs the README from the live spec and servers, then compares what ships (`README.md`, `package.json`, `bun.lock`, `src`, `manifest.json`) against the last `v*` tag. When something differs it bumps the patch version in all three version files, builds, tests, publishes to npm with provenance, commits, tags and attaches the `.mcpb` to a GitHub release. When nothing differs it exits cleanly. Dispatch always releases, with the bump given as input. CI runs on every push and pull request and weekly, so the live listing test and the container probe keep running between pushes.
